# AO3 metadata extraction

Scope: how AO3 preface HTML embedded in an EPUB is parsed into structured
metadata, and how tag canonicalization/synonym expansion is stored. For how
that metadata is used in search/filter, see `search-and-filter.md`. For the
EPUB container/HTML parsing this reads from, see `epub-parsing.md`. The raw
HTML shapes this extractor parses are described in
`docs/ao3_epub_html_reference.md`, a local-only file that is gitignored because
it contains non-open-source material (see `CLAUDE.md`, "Local-only files").
It may be absent from your checkout; do not copy its text into tracked files.

## AO3 Metadata and Tags

`AO3MetadataExtractor` parses AO3 EPUB preface HTML with SwiftSoup and returns `AO3MetadataRecord`. Extraction reads spine items raw (`EPUBParser.rawXHTML(for:archive:)`, one `Archive` per book, `parse(skipTOC: true)`) and parses each once with SwiftSoup. It does not use the reader's `html(for:)`, because `sanitise` rewrites the preface and title page for display (it removes `p.message`, headings and the `div.byline` wrapper depending on `ao3WorkLayoutOrder`), which made extraction results depend on a reader preference. `LibrarySession` tries spine[0] first (AO3 EPUBs reliably place the preface there), falling back through the first 8 spine items for non-standard files or external fanfiction tools, stores successful extraction in `ao3_metadata`, and stores skipped/failed attempts in `ao3_extraction_diagnostics`. `book_index.word_count` is AO3's stated word count when the preface has one. Otherwise the book's markup is counted with `EPUBWordCounter` (one open archive, no regex; same strip-tags-then-split-on-whitespace rule as before). On Re-extract (`forceAll`), books that already have a `book_index` row and no AO3 stated count keep their stored row and are not recounted. Extraction runs concurrently via a capped `TaskGroup` (up to 8 books in flight at once), flushing to the DB every 50 books or every 5 seconds, whichever comes first (`ExtractionBatchPolicy`), with `Task.yield()` between flushes so read queries can cut in. The run uses `.utility` priority at library open and `.userInitiated` for the Preferences Re-extract action (`startAO3Extraction(priority:)`); `.background` was dropped because it throttles CPU and disk I/O on Apple silicon.

### Shared Work ID & URL Resolution
`AO3MetadataExtractor` centralizes work ID parsing and URL normalization across native AO3 and external generator frontmatters:
- `AO3MetadataExtractor.parseWorkID(fromHref:)`: Extracts numeric work IDs from `/works/<digits>` path segments via a compiled `NSRegularExpression`. Used uniformly across native AO3 parsing and external frontmatter engines (`FanFicFareParser`, `FicLabParser`, `FicHubParser`).
- `AO3MetadataExtractor.absoluteAO3URL(_:)`: Converts relative `/works/...` hrefs to canonical `https://archiveofourown.org...` URLs without duplicated ternary checks.

### Shared Byline Authors Scanning
Chapter byline extraction (`div.byline`) is unified via `AO3MetadataExtractor.findBylineAuthors(spineCount:after:window:loadHTML:)`:
- **Window semantics**: Scans spine indexes from `prefaceIndex + 1` up to `min(prefaceIndex + 1 + window, spineCount)`. Default `window: 2` checks the next 2 spine items, returning on the first non-empty author list or `[]` if none is found.
- **Caller isolation**: `LibrarySession` supplies a raw XHTML reader (`try? parser.rawXHTML(for: parser.spine[$0], archive: archive)`) during indexing; `CalibreLibraryWriter` supplies `try? parser.html(for: parser.spine[$0], userCSS: "")`. The outer preface scan loops remain separate on purpose: `LibrarySession` inspects 8 items raw with non-AO3 generator diagnostics on ~70k books, while `CalibreLibraryWriter` inspects up to 5 items during single-book export and library author fallback.

Extracted fields include story URL, work ID, author username, kudos, word count, chapter counts, completion, language, dates, fandoms, relationships, characters, additional tags, categories, AO3 collections, and AO3 series.

Series metadata is resolved to persistent rows in `series` and book memberships
are stored in `series_cache`. AO3 IDs and Calibre series IDs have stable keys;
name-only entries reuse a trimmed, case-folded, whitespace-normalized identity.
The key is stored once and is not reconstructed from a later display-name
change. Re-extract clears and rebuilds memberships while leaving series rows
and any future series-level flags intact. See `metadb-and-migrations.md` for
the required one-time series-cache reset before using the schema-changing build.

### Multi-Engine External Fanfiction Parsers (FanFicFare, FicLab, FicHub)

In addition to official AO3 EPUB downloads (`archiveofourown.org`), `AO3MetadataExtractor` and `LibrarySession` support EPUB frontmatter generated by external tools archiving AO3 works:
- **Fast-path detection**: If the first spine item contains `#preface` and `archiveofourown.org`, the native high-speed DOM parser is used immediately.
- **FanFicFare (`FanFicFareParser`)**: Identifies `class="fanficfare_titlepage"` or `.metadata` blocks generated by FanFicFare. Extracts AO3 work ID, metadata fields (fandoms, characters, relationships, tags, series, kudos, word counts), and summary notes. Non-AO3 stories (e.g. from FanFiction.net, Fimfiction) are intentionally detected and skipped with clear diagnostics ("Non-AO3 story in FanFicFare preface").
- **FicLab (`FicLabParser`)**: Identifies `class="ficlab-title"` or `meta[content*='ficlab']`. Parses FicLab's two-column metadata tables, badge structures, and tag links.
- **FicHub (`FicHubParser`)**: Identifies `class="fichub-title"` or FicHub table headers, parsing standard story links, metadata spans, and AO3 series details.

Spine scanning examines up to the first 8 spine items to locate valid title pages and metadata prefaces across varying tool generator formats. Non-AO3 stories from external aggregators are recorded as non-AO3 skips without cluttering extraction diagnostics as broken works.

### Tag Seeds & Synonym Resolution
Configured AO3 tag seed databases (`ao3_tag_seeds.db`) are queried **directly in read-only mode** via `AO3TagSeedDatabaseConfig.shared`. Tag seed rows are no longer duplicated into each library's `ambrosia_meta.db`, saving ~117 MB per library and eliminating duplicate tables (`canonical_tags`, `tag_synonyms`, `tag_parent_links`, `tag_subtag_sections`). Any legacy copies of these tables in existing `ambrosia_meta.db` files are automatically dropped and vacuumed on library open.

`canonicalTerm(for:)` and `expandedTerms(for:)` on `AmbrosiaMetaDB` delegate directly to `AO3TagSeedDatabaseConfig.shared`, providing canonicalization and synonym expansion across search and filter pipelines without redundant disk copies.

### Extraction Diagnostics & Debugging Failed Works
When extraction encounters a non-AO3 EPUB or malformed preface structure, the failure reason is recorded in `ao3_extraction_diagnostics (calibre_id, story_url, reason, attempted_at)`. When metadata is successfully extracted for a work, any existing diagnostic for that work is automatically removed. On open and diagnostic queries, stale diagnostic rows for works present in `ao3_metadata` are pruned automatically.

In **Settings ▸ Data**, users can view extraction progress (Extracted vs. Failed vs. Total) and click **"View Diagnostics…"** to open a diagnostic inspection sheet. The sheet displays the book title, author, and specific parsing error message (e.g. missing preface elements, malformed HTML, or unparseable metadata), with a button to open each failed book directly in the reader for inspection.
